Definition of an Object

Object: a user-defined complex data type

  • An object has a state (variables) and methods (behavior or operations).

An object has four defining characteristics

  • Identifier: a system-wide unique ID for the object
  • Name: an optional unique database name
  • Lifetime: persistent or transient
  • Structure: construction through a type constructor

Object Structure

  • The state of a complex object may be constructed from other objects or values through a type constructor.
  • An object can be represented as (I, C, V)
    • I is a unique ID
    • C is a type constructor
    • V is the object state
  • Basic types: atom, tuple, and set
  • Collection types: list, bag, and array

Object Oriented Concepts

Abstract data types

Class definitions extend the database with complex attribute types.

Encapsulation

Implementation details for operations and object structure remain hidden.

Inheritance

Data and behavior can be shared through a hierarchy, supporting code reuse.

Polymorphism

The same operator can support multiple types through overloading.

Object Oriented Database

Abstract data types

  • A database system that incorporates the important object-oriented concepts.

Additional features

  • Unique object identifiers
  • Persistent object handling

Object Query Language (OQL)

  • Declarative query language
  • Not computationally complete
  • SQL-based syntax using SELECT, FROM, and WHERE
  • Supports user-defined operators and types

Example of OQL

The following query asks: “What are the names of the black products?”

SELECT DISTINCT p.name FROM Products p WHERE p.color = 'Black';

The syntax is valid in SQL and OQL, but each language returns a different type of result.

Object Oriented SQL — SQL3

  • Foundation for object-oriented database systems such as Oracle8 and DB2.
  • Combines relational and object-oriented features.
  • Relational features: new data types and predicates, enhanced semantics, added security, and active database behavior.
  • Object-oriented features: support for functions and procedures.

User Defined Datatypes

Creating a row type:

CREATE ROW TYPE AddressType ( street CHAR(50), city CHAR(20) ); CREATE ROW TYPE StarType ( name CHAR(30), address AddressType );

Creating Data Types

Creating tables from the row types:

CREATE TABLE Address OF TYPE AddressType; CREATE TABLE MovieStar OF TYPE StarType;
  • Instances of row types become tuples in a table.

Sample Query

Find the names and street addresses of movie stars who live in Columbus:

SELECT MovieStar.name, MovieStar.address.street FROM MovieStar WHERE MovieStar.address.city = 'Columbus';

Complex Data & Queries

Addressing these queries

  • Link the database to landmarks on a topographic map.
  • Examine the caption for each slide.
  • Implement image understanding programs.
  • Inspect images and determine their attributes.

These queries require dedicated methods.

Creating Function

CREATE FUNCTION one() RETURNS INT AS 'SELECT 1 AS result' LANGUAGE SQL;

Calling the function:

SELECT one() AS answer;
Answer
1

Creating “Table” & “Methods”

Implementation

CREATE TABLE slides ( id INT, date DATE, caption DOCUMENT, picture CD_IMAGE, METHOD containsName(name VARCHAR) RETURNS BOOLEAN AS EXTERNAL NAME 'matching' LANGUAGE C );

Implementation

Find a picture of a reservoir with a low water level located in Sacramento:

SELECT slides P, landmark L WHERE isLowWaterLevel(P.picture) AND P.containsName(L.name) AND L.name = 'Sacramento';

Object-Relational Mapping

  • Object-Relational Mapping (ORM) systems sit on top of traditional relational databases.
    • The implementor maps objects to relations.
    • Objects are transient and have no permanent object identity.
    • The system fetches relational data and constructs objects.
    • Updates generate corresponding insert, update, or delete statements.
  • Hibernate ORM is widely used.
    • Its API manages transactions and retrieves objects.
    • Its query language operates on the object model, then translates queries to SQL.
  • Limitation: mapping adds overhead, especially for bulk updates.

Advantages of OODBMS

  • Designers can specify both object structure and behavior through methods.
  • Object-oriented languages such as Java and C++ integrate more naturally.
  • The database supports complex and user-defined types.
  • Encapsulation keeps operations together with the data they use.
